## 1. 为什么启动这个项目

### 1.1 真实业务背景

运营关注美国婴幼儿看护监控市场，曾以淘宝在售的萤石 C6c 类摄像头作为产品参考。团队**尚未决定最终做什么产品**；希望先研究美国市场真实需求、消费者购买行为、竞品、交易环境、成本与监管约束，再决定是否值得进入。如证据支持继续，才讨论自主研发、合作开发、ODM/OEM 等路径。

### 1.2 需要解决的问题

当前市场判断很容易依赖零散选品经验、个别竞品销量页面或若干社媒讨论。业务需要一种更可靠的做法：把分散资料转化为**可追溯、可质疑、可更新**的证据，并明确区分需求存在、进入机会、盈利可行性。

### 1.3 双层目标

**当下业务目标（必须优先）：** 为业务负责人回答“美国婴幼儿看护监控市场是否存在值得进一步验证或进入的机会？”提供决策支持，而不是替代业务负责人作决定。

**长期工程目标（条件成立后演进）：** 以真实研究中的重复性工作为切入点，逐步建设可复用的市场研究与消费者洞察能力，将来能够迁移到其他商品、行业和市场，并有机会为现有 AIGC 内容生产提供经过核实的消费者洞察。

长期目标不是 P0 的开发授权。

## 3. 研究的核心决策链

必须依次区分以下问题，不得跨越推论：

1. **需求存在吗？** 是否有消费者在购买/使用此类方案，解决哪些实际问题？
2. **细分机会存在吗？** 现有替代方案哪里不足；新进入者为何有机会？
3. **我们的进入可行吗？** 在可能的渠道、费用、合规与能力边界下是否值得投入？
4. **是否进入下一阶段？** 如进入，再决定要验证的产品主张与开发模式。

**不成立的推断：** 讨论很多 → 市场很大；差评很多 → 机会很大；某产品功能多 → 我们必须复制；销量高 → 新品牌容易赚钱；技术能做 → 应该研发。

## 4. 首个案例的研究范围

### 4.1 纳入

- 美国消费者围绕婴幼儿看护监控的购买与使用决策；重点 0–3 岁家庭，允许覆盖孕期准备购买场景。
- 消费者目前使用的**所有相关替代方案**：普通室内摄像头、专用智能婴儿监控器、非联网独立显示屏产品、混合型产品等。
- 需求、场景、付费与替代行为、竞品定位、定价和交易线索、市场趋势、渠道、成本、监管和运营约束。
- 消费者自然讨论与真实买家评价；在合规条件下使用可追溯的公开资料。

### 4.2 不纳入／不预设

- **不预设**：是否 Wi-Fi、是否独立屏幕、是否自研硬件、是否带 AI、售价、形态、镜头规格、品牌定位。
- 不将“萤石 C6c 的功能”转换成需求规格或市场结论。
- 不用社媒文本计算美国人口代表性的购买率或品类市场份额。
- 不在 P0 写爬虫、调用模型、建数据库、搭 Agent、设计前后端或安排全面研发。
- 不采集私人家庭视频、婴幼儿影像或其他不必要的个人信息。

## 5. 分阶段推进及门禁

| 阶段 | 目标 | 必须具备的证据 / 交付 | 不能偷换的结论 |
| --- | --- | --- | --- |
| **P0** 业务建模 | 明确决策问题、人工流程、证据与首轮研究范围 | Charter、人工研究基线、P1 计划，运营核对 | P0 文档完成 ≠ 市场有机会 |
| **P1** 人工真实研究 | 用小样本验证研究路径，并形成第一版市场机会观察 | 原始来源索引、竞品地图、需求主题、反例、约束清单、研究报告 | 小样本主题 ≠ 市场占有率或销售预测 |
| **P2** AI 能力验证 | 比较人工与 AI 在具体重复性任务上的效果 | 任务定义、对照样本、错误分类、质量评测、成本记录 | 模型调用成功 ≠ 分析准确 |
| **P3** 最小工程闭环 | 仅将验证有效的步骤产品化 | 可恢复研究任务、证据关联、复核、导出与运行记录 | 工程 PASS ≠ 业务获益 |
| **P4** 多案例复用 | 检验方法能否迁移 | 第二/第三案例、可迁移模块与例外 | 单品类成功 ≠ 通用市场研究能力 |

**阶段间默认不自动授权。** 每一阶段先确认验收证据与继续投入的理由。

## 7. 参与角色（待按实际人员确认）

| 角色 | 责任 | 不应承担的推定责任 |
| --- | --- | --- |
| 运营 / 品类负责人 | 提供商机、说明渠道、验证痛点是否影响业务，复核结论 | 不是单凭主观喜好替代证据 |
| 研究执行者 | 制定采样、整理证据、寻找反例，说明限制 | 不负责替业务方决定投资 |
| 技术 / 供应链人员 | 给出可行性、成本、维护与合规核对信息 | 不在 P0 就承诺全栈研发 |
| 业务决策人 | 定义预算、可接受风险、继续/补证/暂停条件 | 不应将未知市场信息当作已证实 |

未指定人名时，不自动填入责任人或宣称已审批。

## 8. 证据与结论治理原则

1. 每项重要判断记录 `结论 — 证据链接 — 时间 — 覆盖人群 — 反例 — 限制 — 负责人`。
2. 区分 `FACT / USER-REPORTED`、`FACT / EXTERNALLY VERIFIED`、`HYPOTHESIS`、`DECISION`、`OPEN QUESTION`，必要时标记 `ESTIMATE`。
3. 外部事实注明验证日期、地区、产品型号、数据口径；旧来源不能伪装成实时事实。
4. 记录不利证据；禁止只保留支持研发的评论。
5. 不用编造精确比例、样本量或市场份额来填补数据缺口。
6. 后续若用 AI，总结必须能回溯原始来源，人工保留纠错权。
